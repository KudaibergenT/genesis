# Вопросы организаторам и принятые трактовки

| # | Вопрос | Наша трактовка сейчас |
|---|---|---|
| 1 | Усечение по шагам/времени засчитывается как пустой ответ? На чистой книге это даёт +0.80. | Да, строго по ТЗ. Отдельно считаем `strict_timeout_reward = −1`. |
| 2 | Что входит в `inspection_steps`: submit, ошибочные шаги, калькулятор? | Все шаги до submit, включая ошибки и калькулятор; submit не входит. Oracle = 1.0. |
| 3 | При k ≥ 10 атака «30 выводов, включающих всю правду» даёт по официальной формуле ≥ 0 (0 / +0.073 / +0.143 при k = 10/11/12). Это ожидаемо? | Формула не меняется, генератор поддерживает 0–12 (по умолчанию до 12). Ограничение задокументировано в `docs/reward_analysis.md`; реальная атака без знания эталона получает −1. |
| 4 | Можно ли класть дополнительные факты (service_period, order_ref) внутрь `line_items`? | Да, без изменения набора полей верхнего уровня. |
| 5 | Формат ID доказательств для fx.csv (у файла нет id)? | Натуральный ключ `date\|source\|target`. |
| 6 | Повторный submit после завершения? | Ошибка `episode_finished`, итог не меняется, шаг не тратится. |
| 7 | Как запускается официальная проверка: Docker или интерпретатор? | Оба: `scripts/docker_run_all.sh` (основной путь) и `python3.11 scripts/run_all.py`. |
| 8 | Допустимо ли включать в эпизод окно следующего периода для проверки cut-off? | Да: 5 дней после period_end, объявлено в manifest/policy как следующий период. |
| 9 | В какой валюте заявлять FX- и cut-off-ошибки? | В валюте учёта (базовой); опубликовано в `policy.issue_conventions`. |
| 10 | Отрицательные суммы для корректировок и возвратов допустимы? | Да: total_minor < 0 — корректировка, amount_minor < 0 — возврат клиенту. |
